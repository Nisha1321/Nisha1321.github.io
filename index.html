Research

Making LLM systems measurable and trustworthy

I'm interested in how LLM-based systems fail and how we can tell. Most of what I've learned so far came from building systems and then measuring them carefully enough to see where they broke. I want to develop this into a research direction through doctoral training.

Interests

Retrieval failure modes

Why retrieval-augmented generation misses relevant passages, and how chunking, embeddings, and ranking each contribute.

Evaluation methodology

Building test sets and metrics we can trust, including checking whether the measurement itself is wrong.

LLMs for software engineering

Code generation, testing, debugging, and program repair, and how reliable those tools really are.

Trustworthy and agentic systems

Interactive LLM systems that act on their own, and how to make their behavior predictable and safe.

Retrieval failure

Chunking diluted a key sentence

A distinct sentence shared a chunk with unrelated boilerplate, so its embedding drifted and retrieval missed it. The cause was the chunk boundary, not the retriever.

Measurement failure

The eval set was wrong

A date-format keyword mismatch made correct answers score as misses. Some apparent system failures came from the test instrument.

Index contamination

Duplicate chunks pushed results down

Non-idempotent ingestion added copies of chunks. A uniqueness constraint on filename and course fixed it for good.

Method

Hybrid retrieval with RRF

Combined pgvector similarity with Postgres full-text search through Reciprocal Rank Fusion to recover exact-term matches.

Case study · Security evaluation

Independent · Python

Sandbox Escape Finder

A tool that tests how well RestrictedPython holds up against known Python sandbox-escape techniques, combining static analysis with dynamic probing so each flag is backed by evidence.

10/10attacks flagged
0escapes
17tests
Static analysis

Five AST detectors, one tree walk

Flags __subclasses__ traversal, __globals__ and closure access, builtins reloads, frame introspection, and format-string attribute access.

Dynamic oracle

Three independent escape signals

A canary file outside the sandbox, a per-payload secret, and denylisted module loads. Any one of them confirms an escape.

Result

Flagged, but contained

Against RestrictedPython 8.5 with default guards, all 10 attack payloads were flagged and none escaped. Eight were blocked at compile time, two at runtime. Two payloads trace back to CVE-2023-37271 and CVE-2023-41039.

Known limit

Runtime-built strings slip past

The format-string detector only reads literals, so a format string assembled at runtime would not be caught statically.
